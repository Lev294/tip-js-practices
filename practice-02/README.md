## Модель и файлы

Для задачи использую четыре поля: `id`, `title`, `completed` и `priority`. В `id` храню положительное безопасное целое число. Название после `trim()` должно содержать от 1 до 100 символов. Статус — `true` или `false`, приоритет — `low`, `medium` или `high`.

- [data.js](src/data.js) — общий набор и шесть задач варианта 7.
- [task-service.js](src/task-service.js) — девять функций для работы с задачами.
- [main.js](src/main.js) — общий сценарий, мой вариант и вывод результатов.
- [checks.js](checks.js) — проверки преподавателя.
- [checks.own.js](checks.own.js) — три моих проверки.

Функция поиска возвращает задачу или `undefined`. Функции выборки возвращают новые массивы, а функция сводки — объект с числами.

При создании получаю `{ ok: true, task }`, при изменении списка — `{ ok: true, tasks }`. Если данные неверные или задача не найдена, функция возвращает `{ ok: false, error }`.

Задачи ищу по `id`, а не по индексу: например, у второй задачи общего набора `id = 4`. Процент округляю через `toFixed(1)` только при выводе. При изменении создаю новый массив и копию выбранной задачи, поэтому исходные данные сохраняются.

## Общий сценарий

Добавил задачу 20, выполнил задачу 4, переименовал 10 и удалил 7. Затем попробовал ещё раз добавить задачу 20.

В таблице числа идут в порядке: всего / выполнено / осталось / прогресс.

| Этап | Ожидание | Фактически |
| --- | --- | --- |
| Исходный набор | 4 / 2 / 2 / 50.0% | 4 / 2 / 2 / 50.0% |
| Добавление 20 | 5 / 2 / 3 / 40.0% | 5 / 2 / 3 / 40.0% |
| Выполнение 4 | 5 / 3 / 2 / 60.0% | 5 / 3 / 2 / 60.0% |
| Переименование 10 | 5 / 3 / 2 / 60.0% | 5 / 3 / 2 / 60.0% |
| Удаление 7 | 4 / 3 / 1 / 75.0% | 4 / 3 / 1 / 75.0% |
| Повторное добавление 20 | Отказ; прежнее состояние | Ошибка: задача с id 20 уже существует; состояние сохранено |

В конце остались задачи с id `[1, 4, 10, 20]`. В работе осталась только задача 20. Сравнил `demoTasks` до и после сценария: исходный массив не изменился.
